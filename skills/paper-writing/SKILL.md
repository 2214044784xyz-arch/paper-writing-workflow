# 论文写作 / 修改工作流

这个 skill 把七个开源写作技能拆成可组合的工序，用来写和改**中文学术论文**（英文摘要与投稿信同理，见 `references/01`）。

七套技巧各自解决一层问题，单独用任何一套都会在别的层过度或不足：

| 来源 | 它真正管的那一层 | 一句话 |
| --- | --- | --- |
| Writing Agent | 结构 | 从选题立场到传播测试的全流程骨架 |
| ShuorenHua | 事实 | 先锁定事实，再谈怎么改写 |
| Humanizer（EN） | 风格 | 英文 AI 腔的 26 条特征，分 A–F 六组（维基百科「Signs of AI writing」） |
| Humanizer-zh | 语法 | 中文 21 条痕迹（ai-zixun 分支）；另一分支 moli238 为 36 条六类 |
| stop-slop | 硬规则 | 极简禁令：停套路、删填充、破结构、用主动语态 |
| AI-Flavor-Remover | 执行 | 可直接跑的改写 prompt 结构 |
| De-AI-Prompt-Enhancer | 前置 | 先把「需求」改写清楚，再让模型动笔 |

## 1. 五条铁律（动手前先读）

| # | 铁律 | 具体做法 | 违反的后果 |
| --- | --- | --- | --- |
| 1 | **事实锁定** | 改写前先列 Fact Ledger：数字、年份、样本量、系数、[n] 引文、变量名、方法名、结论方向 | 改完漂亮了，但结论被悄悄改掉 |
| 2 | **分节力度** | 摘要/引言/综述可重写；方法/结果只做轻度清理；结论只改表述不改边界 | 把「结果」写活，等于伪造 |
| 3 | **不新增事实** | 只做同义重述与结构重排；不加文献、不加数据、不加因果 | 学术不端风险 |
| 4 | **可回溯** | 每处改动给「原句 → 改句 → 理由」三列 | 导师/审稿人问「为什么改」时答不上来 |
| 5 | **检测率不是 KPI** | 目标是证据密度、逻辑链、可读性；指数降不下来就停手 | 为过检测把论文改得不像论文 |

> 最后一条要反复说：AI-Flavor-Remover 的作者自己也提醒，「AI 味」在某些场景未必是缺点。学术写作的复现性、hedging、术语一致性，本来就是「机器感」的来源。

## 2. 阶段流水线（P0–P7 主线，P8 可选）

| 阶段 | 做什么 | 调用 | 产出 | 通过标准 |
| --- | --- | --- | --- | --- |
| **P0 诊断** | 扫一遍全文，按节统计痕迹密度 | `scripts/ai_trace_scan.py` | 扫描报告 | 知道「哪一节、哪一类」最重 |
| **P1 立场** | 一句话论点 + 贡献句 + 边界句 | `references/07` | 论点卡 | 能用一句话说清「本文反对/补充了谁」 |
| **P2 骨架** | 大纲 + 开头测试 | `references/07` | 三级大纲 + 开头 3 版 | 开头第一段就能读出缺口 |
| **P3 草稿** | 按节展开，一段一个论点 | `references/07` `09` | 初稿 | 每段有 claim + evidence + warrant |
| **P4 台账** | 抽出全部不可动信息 | `references/05` | Fact Ledger | 数字/引文/变量一个不漏 |
| **P5 硬规则** | 机械清理：填充词、套话、排比、破折号 | `references/03` `02` `01` | 清理稿 | 删完语义没丢 |
| **P6 还原** | 把「表演式写作」拉回真实表达 | `references/05` `04` | 改写稿 | 读起来像人写的，且更像作者本人 |
| **P7 审稿** | 审稿人视角挑刺 + 摘要/结论测试 | `references/07` `09` | 意见清单 | 每条意见能落到具体段落 |
| **P8 前置优化**（可选） | 把「需求」改写成带约束的指令 | `references/06` + `09-G` | 增强版 prompt | 场景/读者/禁忌/验收标准齐全 |

P0→P3 用于「写」，P4→P7 用于「改」，可单独调用。只改一段时，跳过 P0，直接 P4→P5→P6。

## 3. 分节力度表（全篇最重要的一张表）

| 章节 | 允许 | 禁止 | 改写目标 |
| --- | --- | --- | --- |
| 摘要 | 重写句式、合并句、删套话 | 改数字、改结论方向、加新发现 | 200–300 字内说清「问题—方法—发现—含义」 |
| 引言 | 重排逻辑、换开场、删背景铺陈 | 编造研究缺口、夸大贡献 | 第三段结束前必须出现「本文做什么」 |
| 文献综述 | 合并同类、改叙述节奏、去「研究表明」模糊归因 | 改文献结论、加未读文献 | 从「谁说了什么」推进到「还没解决什么」 |
| 假设/模型 | 轻度润色 | 改变量关系、改方向、改符号 | 只让表述更紧，不碰命题 |
| 方法 | 只删填充词、统一术语 | 改样本、改模型、改识别策略 | 可复现 |
| 结果 | 只删填充词、统一表述 | 改系数、改显著性、改表格文字含义 | 与表格逐字对得上 |
| 讨论/结论 | 重写句式、压缩、去升华 | 超出数据下结论、加政策建议的新论据 | 边界清楚，留一个未解问题 |

细则、学术套语白名单、中英差异见 `references/08-academic-guardrails.md`。

## 4. 路由：用户一句话 → 走哪条路

| 用户说 | 你做什么 | 关键动作 |
| --- | --- | --- |
| 「帮我降 AI 味 / 降重 / 过检测」 | P0 → P4 → P5 → P6 | 先出扫描报告，再按节改；不承诺检测率 |
| 「这段读起来像机器写的」 | P6 单段，力度中 | 挑 3 处最像的地方改，给对照 |
| 「审稿人说论证跳跃 / 逻辑不清」 | P7 | 逐段问「claim—evidence—warrant」缺哪个 |
| 「帮我写引言 / 开题 / 综述」 | P1 → P2 → P3 | 先要立场，再要大纲，最后才写 |
| 「润色英文摘要 / 投稿信」 | `references/01` + P5(en) | 英文用 Humanizer 的规则，不用中文的 |
| 「帮我改 prompt」 | P8 | 用 `09-G` 的模板补场景/读者/禁忌/验收标准；约束清单参考 `06` |
| 「结论写不出深度」 | P7 结论测试 | 回到「边界 + 未解问题」，不要升华 |

## 5. 执行规范

1. **一次一段**，单段 ≤ 400 字；整篇修改先出报告再分批。
2. **三列输出**：原句 / 改句 / 理由。理由写「删了什么、为什么」，不写「更通顺」。
3. **保护区**：数字、`[n]`、变量名（如 `Exposure_{i,t}`）、英文术语、引号内原文、图表题注，一律不动。
4. **不替作者做判断**：涉及「这个结论是否成立」时提问，不擅自改。
5. **改完复述**：用两句话复述改后段落的主张，让作者确认没走样。
6. **报告落盘**：用 `assets/revision-report.md` 模板，方便回滚与答辩说明。

---

## 6. 交付前自检（10 问）

1. 每个数字都能在 Fact Ledger 里找到出处？
2. 每处 `[n]` 都还在原位、没有被合并或删除？
3. 有没有出现原文没有的因果词（导致/使得/因而）？
4. 有没有把「相关」写成「影响」、把「显著」用在非统计语境？
5. 摘要里有没有出现正文没有的结论？
6. 方法/结果节是否只动了语言、没动实质？
7. 改后的段落，作者本人读得出来是自己写的吗？
8. 连续三段是不是同一个节奏（都「首先…其次…最后」）？
9. 有没有为了去 AI 味把学术 hedging 全删了（可能/在一定程度上/初步证据）？
10. 报告里的「理由」列，能不能直接贴进给导师的说明？
