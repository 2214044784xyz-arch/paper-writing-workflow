# Writing Agent（系统级：从选题到传播的全流程写作）

> 来源：https://github.com/dongbeixiaohuo/writing-agent （`.claude/skills/workflow-producer/SKILL.md` + `.claude/workflows/collab_v2.json` + `.claude/agents/*.md`，commit `5a2acb4`）；原文阶段数 23（模式 B 主链 20 个编号阶段，另含模式 C 的 0a/0b 与可选 Stage 14）
> 原文合并存档：`vendor/writing-agent/SKILL.md`

## 一句话定位

一套「导演 + 18 个阶段子代理 + 文件协议 + 门禁脚本」的中文长文流水线：不负责把句子写漂亮，而是保证判断可被研究推翻、事实有账本、标题承诺被正文兑现、评审意见先互相隔离再由导演合并。

它针对的失败模式很具体：模型写作常见的三处塌陷——判断看着有理却不可反驳、事实看着具体却查不到出处、标题与开头承诺的东西正文接不住。文体是第一分叉：争议评论查判断与反方，解释分析给机制与边界，叙事观察保护视角与留白，实用经验说清条件与失败方式。

## 阶段流水线

原文用一个 JSON 契约定义三种模式：**A 轻量**（`1 → 6 → 7 → 9.5`，只写正文 + 可选审稿）、**B 协作**（下方 20 个阶段全链）、**C 选题**（`0a → 0b → 1`，之后交给 B）。下表顺序即契约 `stages` 数组顺序，含两处反直觉但真实存在的排序：`0` 在 `1` 之后、`11` 在 `10.5` 之前。

| 阶段 | 输入 | 动作 | 产出物 | 通过标准 |
|---|---|---|---|---|
| 0a 选题生成 | 领域、读者、`_topic_pool/` | 热点扫描 + 资产盘点 + 选题池查重 + 竞品分析 | `[时间]-topic-candidates.md` | 候选真实落盘；查重比较主题实体/核心冲突/读者，不比起标题字符串 |
| 0b 选题验证 | 候选文件 | 查未知概念来源、检验读者所得与差异化、找反例 | `[时间]-topic-validation.md` | 给出「推荐写/调整后可写/材料不足」及证据，不按热度加权 |
| 1 写作需求澄清 | 用户请求 | 13 项简报要素 + 按缺口采集作者一手素材 | `01_theme.md` | 写明风格确认状态、案例领域边界、必保概念 |
| 0 记忆装载 | `01_theme.md` | 扫 `99_episode.md`/表现复盘，按来源分级聚合 | `00_memory_packet.md` | ≤50 行；只有 `user_edit` 可称偏好；无经验也要写一行 |
| 1.5 论证假说（立场） | `01_theme.md` | 按文体选论证模式，出可被推翻的假说 | `01b_position.md` | 含假说、最强反例、研究如何推翻、适用边界 |
| 2 调研与证据账本 | `01_theme` + `01b` | 列外部事实需求清单、跑反证、标 provenance | `02_scar_tissue.md`、`02_evidence_ledger.json` | 每条 claim 有 evidence_id/来源摘录/use_boundary；至少一次反证尝试，或写明 not_required 理由 |
| 3 大纲 | 1/0/1.5/2 全部 | 按文体选结构，逐段写功能、材料、反证、篇幅 | `03_outline.md` | 段落有实际功能，证据缺口被列出 |
| 4 读者关系与传播 | 1/3/1.5/2 | 先定读者需要什么，再判传播目标是否适用 | `04_share_map.md` | 传播「不适用」要说明理由；无骗评、无强迫站队 |
| 5 具象化 | 2/3/4 | 把妨碍理解的抽象换成类比/画面/条件化行动 | `05_concrete_library.md` | 每项标 provenance 与使用位置 |
| 5.5 标题 | 1/0/1.5/2/3 | 3–6 个真正不同的候选 + 承诺与风险注释 | `04_title.md` | 事实只来自账本；状态为暂定/待选/已锁定 |
| 5.8 开头设计（开头测试） | 3/4/5 + `04_title` | 按文体产 2–4 个 120–300 字原型 | `05c_opening_hook.md` | 每款标起手方式、正文承诺、事实边界 |
| 6 主笔（草稿） | 前述全部准备件 | 跑 `verify_required_files --stage 6 --mode`，按大纲成文 | `draft_v1.md` + `draft_v1_notes.md` | 门禁通过；正文与备注分文件；manifest 已更新 |
| 7 主编审稿 | 正文 + 标题 + 账本 | 只评工艺、结构、语言模板感、作者声音 | `editor_review.md` | 必须修/可选/保留原样，逐条引原文与代价 |
| 8 发布前评审 | 正文 + 标题 + 记忆包 | 判读者是否拿到约定的新收获、承诺是否跳步 | `pre_publish_review.md` | 每个发现引证据，不凑问题、不打分 |
| 9 平台读者压力测试（传播测试） | 正文 + 锁定标题 | 按发布平台选矩阵做定性测试 | `wechat_reader_test.md` | 引具体句子；禁止预测 CTR/完读率 |
| 9.5 集中修订 | 三份评审 + `revision_brief` | 核对 SHA-256，合并取舍，最多两轮 | `revision_result.md`（必要时 `draft_vN`） | 无实质问题就保持同一 `latest_body_file` |
| 10 Humanizer（去 AI 味） | 正文 + 账本 + 记忆包 | 只改能具体指出来的问题，最小修改 | `humanizer_review.md`（必要时 `_humanized`） | 允许结论「无需修改」；不改事实与标题 |
| 11 配图（可选） | 正文 + 标题 | 按简报决定执行或跳过 | 图 + 新正文版本 | 新付费生成须已授权 |
| 10.5 最终事实门禁 | 正文 + 锁定标题 + 账本 | 建快照 → 逐条 claim → 脚本判 passed/blocked | `fact_check_snapshot/claims/report` | 全 SUPPORTED + full + 无 red 才 passed |
| 12 纯文本交付 | 已通过核查的正文 | `auto_clean_hook.py` 清稿 | `_clean.txt` | 本轮真实生成，不拿历史同名文件充数 |
| 12.5 HTML 导出（可选） | `_clean.txt` | 版式 A/B/C/D/N | `.html` | 版式已确认、正文已核查 |
| 13 写作复盘 | `draft_v1` vs 定稿 | 8 维归因，提规则 + 适用边界 | `99_episode.md` | 无差异也要落盘跳过原因；禁止自评总分 |
| 14 发布表现（可选） | `publication_metrics.jsonl` | 追加指标，形成待验证假设 | `performance_reviews/*.md` | 仅用户明确要求时触发 |

注意两点：`6` 与 `9.5` 是同一个子代理（写与改同源）；`7/8/9` 三份评审互相隔离、都不许动正文。

## 每个阶段的关键提问

- **0a**：这个领域你已经写过什么？候选与选题池是主题实体重复，还是只有标题相像？热度有实际来源吗？
- **0b**：读者读完能拿到什么？已有文章缺什么？作者有什么别人拿不出的素材？最强反例在哪？
- **1**：文体是争议评论/解释分析/叙事观察/实用经验哪一种？读者新收获是判断、方法、边界还是观察？案例边界是否已写成「默认非 IT」？
- **0**：哪条规则有 `user_edit` 证据？它的适用条件与反例是什么？没有历史经验是否已如实写明？
- **1.5**：这个作者首先看见什么（利益/结构/人性/代价），判断该从哪一层切入？什么证据会削弱本假说？边界在哪？
- **2**：正文要用的外部事实清单是什么？每项能否指向原始发布方？是否有一次真实的「未找到反证」尝试？
- **3**：每段的功能、所用材料、保留的反证与限定是什么？张力来自问题、难度、反差还是未知（不必树敌）？
- **4**：读者需要理解、陪伴、行动帮助还是讨论空间？传播目标是主要/辅助/不适用？没有自然切口时敢写「未找到」吗？
- **5**：哪个抽象真正妨碍理解？这个类比说明的是哪一层相似关系？条件与限制写清了吗？
- **5.5**：每个候选的正文承诺与风险是什么？标题里的事实数字是否只来自账本？现在是暂定还是已锁定？
- **5.8**：这个开头承诺了什么、用什么起手？事实边界属于哪种 provenance？成稿后首屏还兑现承诺吗？
- **6**：阶段门禁过了吗？论证或叙事是否先完成、再决定传播切口？notes 里证据 id 与待核查项标了吗？
- **7**：结构是否推进问题？段落句式是否机械同构？`illustrative` 有没有被写成真实观察？是否只抄了风格的口头禅？
- **8**：读者拿到约定的新收获了吗？标题承诺在哪一段跳步或失真？有无无来源事实、情绪操控、受众错位？
- **9**：读者为什么继续、会在哪一句退出？分享动机真实存在吗？结尾入口是否允许不同经验？
- **9.5**：`revision_brief` 里的 SHA-256 与当前正文一致吗？事实与承诺是否先于措辞处理？是否已到两轮上限？
- **10**：哪句话空泛、重复或与作者声音不符（要能指出来）？这是问题还是你的偏好（句长、破折号不算）？改动引入新事实了吗？
- **11**：简报要求配图了吗？新增付费生成有授权吗？配图后是否重建了事实快照？
- **10.5**：快照固定了吗？每条 claim 是否 SUPPORTED + full + 无 red？部分支持能不能降黄放行（不能）？
- **12 / 12.5**：`_clean.txt` 是本轮生成的吗？HTML 版式确认来源是谁？
- **13**：初稿到定稿改了什么（8 维）？每条规则来源是 `user_edit` 还是 agent 自评？有没有硬凑规则？
- **14**：是否用户明确要求？指标口径跨平台可比吗？

## 开头测试 / 传播测试具体怎么测

**开头测试（Stage 5.8，考的是「承诺对齐」而非打分）**
1. 按文体出 2–4 个确有差异的原型，每个 120–300 字，标注起手方式、正文承诺、事实边界。
2. 可用起手：已有场景或细节、关键问题或解释难题、低声观察、叙事延迟、反常识判断（仅争议评论）。
3. 明确不要求「暴击/认知撕裂/极短句」；没有 `user_firsthand` 素材不得写第一人称亲历。
4. 落盘时写 `确认状态：暂定/已锁定` 与确认来源；成稿后结合锁定标题复核首屏，不成立就进统一修订，不伪造用户选择。
5. 合格线只有一条：读者读完第一段是否知道这篇要给他什么；答不出，整批原型作废重出。

**传播测试（Stage 9，定性代理指标）**
1. 先按平台选矩阵，不默认套微信场景：公众号（卡片承诺/首屏承接/私域分享/讨论入口）、今日头条（信息流一致性/前三屏推进/信息增量/自然互动）、知乎（问答贴合/专业密度/收藏动机/讨论质量）；平台未知则查标题—首屏一致性、逐段增量、最早弃读点、分享理由、真实入口，并标「发布前需补平台复核」。
2. 每个判断必须引标题或正文的具体句子，禁止「中高」「不错」式空评级；禁止预测 CTR、完读率、推荐量。
3. 固定输出顺序：标题与分发文案 → 最早弃读点（位置+原文+原因）→ 平台矩阵逐项 → 分享/收藏/讨论 → 结论（必须修/可选/保留原样）。
4. 传播目标「不适用」时跳过分享矩阵，只查是否理解、是否愿意继续、承诺是否兑现；无明显弃读点允许写「未发现」。
5. 标题一旦回开重审，旧报告作废，必须重跑 Stage 9；通篇形容词而无引用句的报告视为未完成。

## 降到论文写作时的裁剪

总原则：**保留「先想清楚再写」的骨架，删掉「面向流量」的分支**。论文没有传播，但摘要与结论同样承担「承诺兑现」；没有读者测试，但要预演审稿人；不模仿风格，但有术语与体例的硬约束。因此按「保留 / 改造 / 删除」三档处理下表。

| 阶段 | 论文场景的处置 | 具体怎么改 |
|---|---|---|
| 0a/0b 选题 | 保留，收窄 | 问题从「读者缺什么」换成「文献缺什么」；删热点扫描，改查近三年同题综述 |
| 1 简报 | 保留 | 增目标期刊/栏目、字数格式、必须保留的术语；删风格库与发布平台；一手素材换成实验/访谈/数据 |
| 0 记忆装载 | 保留（可选） | 记忆源改为导师与审稿人历次意见；仍只把明确修改当偏好 |
| 1.5 立场 | 保留，改名「主张」 | 假说＝可被数据反驳的 claim；删「风格内核」约束 |
| 2 账本 | 保留并加强 | 账本升级为文献表（DOI/页码/样本量）；provenance 改为一手数据/引用文献/示意 |
| 3 大纲 | 保留 | 段功能改为「论点—证据—反驳—限定」；篇幅按期刊字数配额 |
| 4 读者关系 | 删除，替换 | 换成「审稿人预设」：他会在哪质疑、会要什么补充数据 |
| 5 具象化 | 弱化 | 只留机制图、量级类比、最小可复现例子；禁止故事化 |
| 5.5 标题 | 保留机制 | 不追冲突与点击，追「关键词可检索 + 承诺可验证」；暂定/锁定照用 |
| 5.8 开头 | 保留，改对象 | 改成摘要与引言首段测试；原型改为问题缺口式、数据反差式、机制断言式 |
| 6 草稿 | 直接复用 | 正文与 notes 分离、notes 存证据定位，正好对应论文的证据链 |
| 7/8 评审 | 合并为一份 | 工艺 + 读者价值合并，但仍坚持「只提意见不改稿」 |
| 9 传播测试 | 改造 | 降级为「摘要能否独立成立、结论是否回答引言问题」，借鉴知乎矩阵的问答贴合与专业密度 |
| 9.5 集中修订 | 保留 | SHA-256 绑定 + 两轮上限照搬，防止无限改稿 |
| 10 去 AI 味 | 保留，收窄 | 只清套话、机械排比、空转折；术语、被动、限定词不算 AI 味 |
| 10.5 事实门禁 | 保留，升级 | 每条 claim 对到文献或数据；「部分支持」不得放行（学术上等于误引） |
| 11/12.5/14 | 按需 | 配图换机制图；HTML 换 LaTeX/Word；不追发布指标 |

## 使用注意

1. 阶段号是硬契约：`0` 排在 `1` 之后（先有简报才装记忆）、`11` 在 `10.5` 之前（配图后必须重新核查）、进 `12` 前必须有 passed。
2. 门禁优先于自觉：缺文件、空文件、格式坏、语义不合格一律退回前序阶段，不接受「已保存」的口头声明，也不要边写边补。
3. 标题与开头先暂定、成稿后锁定；评审只对具体正文版本负责，改标题就重跑传播测试。
4. `user_firsthand / source_verified / illustrative` 三分法是地基，示意情景必须在正文里可辨认；账本为空必须写明原因。
5. 三份评审互相隔离（不读彼此结论），由导演合并；先事实与承诺，再结构，最后措辞，不按票数投票。
6. 只有 `user_edit` 能称「用户偏好」；模拟读者反馈与单篇指标只能形成待验证假设。
7. Humanizer 允许「无需修改」，也禁止为制造人味加口癖或补事实；每轮改稿都要更新 manifest，让旧核查自动失效。
8. 三种模式不要混用输入：A 只用简报与用户素材，硬塞 B 的完整证据树会把轻量任务变成流程表演。
9. 论文场景最常见的两个降级错误：把传播测试做成「摘要顺不顺」，把去 AI 味做成删限定词与被动语态；另外，这套流程的成本主要在前置准备，一句话修改本不该触发它。
